| API-03 | Medium | Authenticated `/auth/me` lacked explicit private/no-store policy. | Authentication middleware and auth router apply `private, no-store`; chat stream additionally preserves `no-transform`. Socket-token already had no-store and is only a regression check, not another finding. |
| API-04 | Medium | 21 multipart text fields and a 65,537-byte field passed upload parsing instead of being rejected at the boundary. | `src/middlewares/upload.middleware.ts`: 20 fields, 21 parts, one file and 64 KiB per field; existing 5 MiB image limit retained. Added a positive test accepting 20 fields plus one image. |
| API-05 | Medium | Stats P1001/P2028 and five knowledge-base operations swallowed database outages as generic 500 responses. | Stats forwards to the central handler; five KB service catches rethrow recognized unavailable-database errors through the shared helper. | API-06 | High | Direct foreign-origin WebSocket handshake returned 101; foreign-origin polling returned 200 despite CORS. | `src/lib/socket-boundary.ts` and `src/server.ts`: explicit `allowRequest`. Direct WebSocket rejection is 400 in this Engine.IO version; polling rejection is 403. Configured frontend and no-origin non-browser handshakes remain accepted; normal session/room authorization is unchanged. |
| API-07 | Medium | `%ZZ` and truncated UTF-8 cookies threw URIError before the socket authentication try/catch. | Shared socket-cookie parser ignores malformed encoded values without throwing, while preserving valid encoded values and equals signs. A production process crash was not observed or claimed. |

Source rationale for API-06: [official Socket.IO CORS documentation](https://socket.io/docs/v4/handling-cors/) distinguishes browser CORS from WebSocket connection restriction and documents `allowRequest`. The actual rejection/acceptance outcomes above were reproduced locally, not inferred from the documentation alone.

Initial outage-test setup incorrectly reset the embedding mock to undefined. That fixture was corrected before the meaningful red run: seven actual outage assertions failed and duplicate-conflict handling passed. The old socket implementation then failed four assertions (two origin checks and two malformed-cookie cases); after repair, the expected direct-upgrade rejection was corrected from assumed 403 to the observed Engine.IO 400. No assertion was changed to permit an accepted foreign handshake.
